## 实时条（header 下方）

- **交易时段**（周一~五 9:15-11:35 / 12:55-15:05，或腾讯 marketStat 判定开市）：30s 自动轮询。
- **盘外**：打开时拉一次快照并标注（如「● 中秋节休市 · 09-24 16:14:01」）。
- 数据源与容错：
  - 腾讯指数 `qt.gtimg.cn`（**变量捕获模式**——该接口忽略 callback 参数，返回 `var v_xxx="..."` 裸赋值，须在 script onload 后读 window 变量）
  - 腾讯 `marketStat`：开/闭市状态与休市原因（含法定假日名）
  - 东财涨停池 `push2ex.eastmoney.com`（真 JSONP 回调；**必须带 `date=YYYYMMDD`**，否则非交易日返回 data:null）
- **v4.8.7 实时增强换源**（原 `push2.eastmoney.com` 全系域名实测 HTTP 000 整段限流）：
  - 题材「内部涨跌比」→ 东财 `datacenter-web.eastmoney.com`（`RPT_F10_CORETHEME_BOARDTYPE` 板块成分股映射，支持 JSONP 回调）+ 腾讯批量行情（`qt.gtimg.cn`，每批 60 只）
    - **匹配策略**：题材名精确等值匹配（`filter=(BOARD_NAME="xxx")`）+ 样本量校验（≥20 只才算真板块）；实测 TOP15 题材中约 1/4 可匹配（板块型），其余为事件驱动型标签（海峡两岸/半年报增长等，东财无对应条目）→ 明确标注「事件型 · 无板块」+ 悬停说明，**不硬凑模糊匹配**（早期 `includes` 式匹配会导致「数据中心」命中 111 页的假匹配）
    - 口径差异需知：存档 `hot[]` 是「当日强势股」（全是涨的，算内部涨跌比恒为 100% 无意义）；本列用的是**板块全部成分股**，含下跌成员，才有甄别价值
  - 量能拆分（上涨/下跌股成交额）→ 腾讯批量行情逐股汇总（全市场号段 ~217 批，并行度 3，实测约 9 秒/3700 只有效样本）；**仅开市时段执行**（收盘后与存档重复无增量）；阈值 `got<1000` 视为不完整则降级不渲染
  - 两条链路彼此**独立**（原实现把 fillTopics 串在 fetchMkt 的 then 里，前置失败导致题材永远空白——已解耦）
- 各通道独立渲染互不阻塞；手动「⟳ 刷新」随时可拉。

## v4.8 全市场K线库（2026-09-27 · 仓库分片架构）

### 为什么不是后端数据库
曾评估「搭后端服务 + 自建数据库拉全市场历史K线」，测算三路线（云服务器+DB 月费 50~100 元 / 对象存储 / 静态分片）后选择零成本等价方案：**git 仓库本身就是持久化数据库**——5,573 个分片文件随提交永久保存（git 历史即时光机），Pages 纯静态伺服，前端按需懒加载单股分片。K线覆盖率从存档内 ~27%（仅上榜/热门股）拉满到全市场沪深A股，不依赖任何会宕机的在线服务。

### 数据层（fetch-kline-all.js）
- **清单枚举**：qt.gtimg 批量行情 60 只/请求扫描 4 段代码区间（共 13,999 候选），无效代码响应缺席=天然过滤，免维护清单接口 → 识别 **5,573 只**
- **历史回填**（`--init` 或 workflow 勾选 kline_backfill）：腾讯 fqkline 单请求 640 根前复权日K（约 2.5 年），工人池 CONC=4 + 80ms 节流，全量 ≈15 分钟；失败率 >10% 中止保护
- **每日增量**（幂等门控后自动执行）：批量行情一网打尽当日 OHLCV，停牌/未开盘（量≤0）自动跳过；分片尾部追加，>700 根 shift 防膨胀，日期比较幂等
- **分片格式**：`{c:"sh600000", n:"浦发银行", bars:[["2025-06-09",11.48,11.48,11.51,11.27,565781],…]}`（日期/开/收/高/低/量）
- **工作流**：daily.yml 新增 `kline_backfill` 手动输入；增量步置于幂等门控之后（节假日零空转不破坏）

### 前端层（lab-kline.js）
- IndexedDB `asent-kline` 库缓存当日分片（file:// 自动降级直连），命中缓存零网络请求
- `_openKline(code)`：800×360 蜡烛图 SVG——红涨绿跌（阳线空心/阴线实心）、MA5/MA10、量带、右侧最新价标注；60/120/250 日区间切换
- 全局搜索回落：存档池无匹配时自动搜全市场清单（≤10 条），建议项带「全市场」徽标，点击直接开K线弹窗
- S6 健康面板新增「全市场K线库 v4.8」状态行（就绪/不可达 + 覆盖数 + 清单时间）

### 数据规模与边界
- 5,573 分片 × 平均 ~25KB ≈ **135MB** 仓库占用（GitHub 建议 5GB 内，余量充足）；每股封顶 640 根，增量超限 shift 淘汰最旧
- 北交所暂不覆盖（fqkline 返回布局不同，v4.9 备选）；本地 file:// 打开时 K线拉取被浏览器 CORS 限制自动降级（线上/HTTP 服务正常）

## 已知限制

- ~~个股腾讯日K覆盖约 27%~~ **v4.8 已解决**：全市场K线分片库拉满到沪深 A 股；v4.8.8 起 S8 统计研判自动取用分片补齐趋势/位置两维，S6「K线覆盖」检查升级为分片库口径（实测 1218/1296 = 94%，余 6% 为北交所码——分片库仅扫沪深号段）。剩余限制：次新股分片 <30 日时位置维缺省（标注「仅N日」）；file:// 离线打开时分片不可达，自动降级旧口径。
- 东财 push2/push2his 全系域名（含 push2delay / 90./82./48. 等分流域名）对本机 IP 实测 **HTTP 000 整段限流**；已切换规避：行业 → 同花顺 881xxx；实时增强 → datacenter-web + qt.gtimg（v4.8.7）。
- **题材「内部涨跌比」覆盖率约 1/4**：仅当题材名能精确匹配东财标准概念板块时才有数据（板块型题材）；同花顺的事件驱动型标签（海峡两岸/半年报增长/大股东增持等）在东财板块库无对应条目，标注为「事件型 · 无板块」。不采用模糊匹配——实测 `includes` 式匹配会让「数据中心」命中 111 页（3.3 万只）的失真结果。
- **通达信（pytdx）不可用决策记录**：8 个公共行情节点（7707/7709 等）目录接口正常（证券列表/板块文件可解析），但**全部行情接口（get_index_bars/get_security_bars/get_security_quotes）返回空**——公共节点已退化为目录节点；扩展行情 7727 端口 IP 全部失联；真实行情服务器 IP 需 TDX 桌面客户端握手后才能发现（超出本工具边界）。故板块排行一年回填改用**同花顺年K接口**（与行业回填同源 881xxx，交叉校验差 0，功能等价）。探针脚本存档 tdx-test/tdx-ex-test/tdx-scan/tdx-probe.py。
- 情绪分位 pct_rank 回填口径为存档期内分位；v1 原始口径基于更长历史（无法从 30 天存档复现，已记录于 meta.dataQuality）。
- 节假日日历需人工维护（meta.holidays）；S2 预测结算依赖存档积累，首次使用全部为「待结算」属正常。
- file:// 下 localStorage 按 file:// origin 共享，跨不同单文件副本会共用同一份实验室数据。
